📖 Phase 1

Vision Document

Strategic overview — what are we building, why, and for whom.

Problem Statement

Used books accumulate in homes while students and readers pay full price for books they need. There is no simple, trust-based, Arabic/English platform in the MENA region that allows people to exchange or sell used books peer-to-peer without complex payment rails or a real-time chat requirement.

Vision Statement

Build the simplest, safest marketplace for used books in the Arab world — where any reader can list, discover, and swap books with zero friction and no payment infrastructure.

Success Metrics

  • 500 listings in first 3 months
  • 200 completed exchanges / sales
  • 40% monthly active user return rate
  • <3 sec page load on mobile
  • Arabic + English fully functional

Target Users

Primary: University students (18–26) seeking affordable textbooks.

Secondary: General readers wanting to trade fiction/non-fiction.

Tertiary: Book collectors reselling rare editions.

Core Value Proposition

A book owner lists in 2 minutes. A seeker finds and requests in 30 seconds. No payment gateway. No chat. Just a simple request → accept → meetup flow.

Technology Bets

Next.js 14 (App Router) + Supabase (Postgres + Auth + Storage + Realtime notifications) + Tailwind CSS. Deployed on Vercel. CI/CD from day 1. Bilingual (ar/en) via next-intl.

Out of Scope (MVP)

Real-time chat, payment processing, delivery logistics, mobile native apps, AI recommendations (post-MVP backlog).

User Stories

Key stories with acceptance criteria, grouped by epic.

Epic: Authentication

As a new visitor
I want to register with my email or phone number so I can list and request books.
Acceptance Criteria
Form accepts email OR phone number with country code
OTP verification sent within 30 seconds
Duplicate account detected and shown a clear error
On success, redirected to "Complete Profile" page
As a registered user
I want to log in with my credentials so I can access my dashboard and listings.
Acceptance Criteria
Login via email+password or phone+OTP
JWT token valid for 7 days, refreshes automatically
Failed login shows specific error (wrong password vs unknown email)

Epic: Listings

As a registered user
I want to add a book listing with photos, condition, and listing type so others can find and request my book.
Acceptance Criteria
Required fields: title, author, category, condition, listing type
Up to 5 photos uploadable; each compressed <500KB
Listing type is "For Sale" (with price) OR "For Exchange"
Listing appears in search within 10 seconds of creation
Autosave draft if user navigates away mid-form
As a listing owner
I want to mark my listing as Sold, Exchanged, or Unavailable so the status is accurate for other users.
Acceptance Criteria
Status dropdown available on "My Listings" page
Sold/Exchanged listings filtered out of main search by default
Users with the book wishlisted receive a notification

Epic: Discovery

As a guest
I want to search and filter books by title, author, category, and condition without creating an account so I can explore before committing.
Acceptance Criteria
Search bar visible on homepage and all listing pages
Filters: condition (multi-select), listing type, price range slider
Results update without full page reload (client-side filtering)
Sort by: Newest, Price (low-high), Price (high-low)
Clicking "Contact Seller" while guest prompts registration modal

Epic: Exchange & Purchase Requests

As a registered user
I want to propose an exchange by selecting one of my own listed books as the swap offer so the seller can evaluate the deal.
Acceptance Criteria
Only "For Exchange" listings show the swap proposal UI
User can select from their own available listed books as offer
Optional message (max 500 chars) attachable to proposal
If user has no listed books, prompted to list one first
Duplicate request to same listing blocked
As a listing owner
I want to accept or reject incoming requests so I can manage my exchanges clearly.
Acceptance Criteria
Requests page shows pending/accepted/rejected with timestamps
Accepting a request auto-rejects all other pending requests for same listing
Requester notified via in-app notification on status change
Accepted request shows requester's contact info (email/phone)

Epic: Admin

As an admin
I want to view platform analytics so I can understand usage and make configuration decisions.
Acceptance Criteria
Dashboard shows: total listings, active users (last 30 days), exchange count
Bar chart: listings by category
Table: most requested books (top 10)
Export data as CSV

Key SQL — Full-Text Search Setup

-- Full-text search vector (auto-updated trigger)
ALTER TABLE books ADD COLUMN search_vector tsvector
  GENERATED ALWAYS AS (
    to_tsvector('simple', coalesce(title, '') || ' ' ||
    coalesce(author, '') || ' ' || coalesce(description, ''))
  ) STORED;

CREATE INDEX books_search_idx ON books USING gin(search_vector);

-- Search query
SELECT * FROM books
WHERE search_vector @@ plainto_tsquery('simple', :query)
  AND status = 'available'
ORDER BY ts_rank(search_vector, plainto_tsquery('simple', :query)) DESC;

// Response 204 No Content

🔄 Contact Requests

POST /books/:id/requests Send contact / exchange request 
{ "message": "Hi, is this still available?",
  "offered_book_id": "uuid" }  // only for exchange listings

// Response 201
{ "id": "uuid", "status": "pending", "created_at": "..." }
// Triggers notification to book owner
PATCH /requests/:id Accept or reject a request 
{ "action": "accept" }  // or "reject"

// On accept:
// 1. Request status → accepted
// 2. Other pending requests → rejected
// 3. Book status → sold/exchanged
// 4. Transaction record created
// 5. Requester notified with owner contact info
// Response 200: { "status": "accepted", "requester_contact": {...} }
